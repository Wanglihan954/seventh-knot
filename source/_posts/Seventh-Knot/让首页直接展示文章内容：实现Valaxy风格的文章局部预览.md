# 让首页直接展示文章内容：实现 Valaxy 风格的文章局部预览

> 首页文章卡片不仅要告诉读者“这里有一篇文章”，还应该展示足够的正文，让读者在进入详情页之前判断它是否值得继续阅读。

<!-- more -->

## Theme Yun 原本缺少什么

原来的首页卡片主要展示标题、日期、字数、阅读时间和分类。它结构简洁，但当文章标题比较抽象时，读者很难知道正文内容。

Valaxy 风格的文章预览更接近“截取文章开头的一段阅读区域”。它不是只有一句描述，也不是完整渲染全文，而是在信息量和首页长度之间找到平衡。

## 把提取逻辑放进 Helper

我在主题脚本中新增：

```text
themes/yun/scripts/helpers/post-preview.js
```

Helper 负责接收文章对象，优先读取 `<!-- more -->` 之前的内容；没有分隔符时，再从正文中选取前几个有效区块，并限制最大字符数。

配置位于 `_config.yun.yml`：

```yaml
post_card:
  preview:
    enable: true
    max_chars: 620
    max_blocks: 4
```

这样预览长度可以调整，不需要每次修改模板代码。

## 为什么不能直接截字符串

文章内容通常包含标题、段落、引用、列表、图片和代码块。如果直接对 HTML 字符串执行 `slice`，可能在标签中间截断，导致整个首页 DOM 结构错乱。

预览逻辑需要完成三件事：

1. 选择适合首页展示的区块；
2. 跳过脚本、样式和不必要的复杂内容；
3. 在安全边界内截断，并返回合法 HTML。

对于大型表格和长代码块，首页只保留有限信息或直接跳过，完整内容仍在文章页中展示。

## Pug 中的展示结构

文章卡片模板只负责渲染 Helper 的结果：

```pug
.post-card-preview(class=preview.truncated ? 'is-truncated' : '')
  .post-card-excerpt.markdown-body!= preview.html
  a.post-card-readmore(href=url_for(post.path)) 阅读全文
```

提取逻辑与展示逻辑分离后，后续修改预览算法不会继续扩大 Pug 模板。

## 使用渐隐表达“还有内容”

被截断的预览底部使用渐变遮罩，而不是突然结束。渐隐层只是一种视觉提示，真正的入口仍是“阅读全文”链接。

移动端减少预览高度和内边距，避免一张卡片占满多个屏幕；桌面端则可以展示更多正文，使首页更接近连续阅读流。

## `<!-- more -->` 仍然有价值

自动提取可以覆盖多数文章，但作者最清楚哪里适合作为预览结尾。在摘要后插入：

```html
<!-- more -->
```

就能稳定控制首页边界。Seventh Knot 系列文章统一在导语后添加该标记，让每篇文章的预览长度保持一致。

## 性能与 SEO

预览在 Hexo 生成阶段完成，不需要浏览器进入首页后再请求正文，也不会增加运行时接口。文章标题仍然使用正常链接，结构化数据继续指向完整文章页。

需要注意的是：首页不应该输出每篇文章的大量正文，否则静态 HTML 会迅速膨胀。字符数、区块数和每页文章数量需要共同控制。

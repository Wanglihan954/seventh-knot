# 打造 Inter-Knot 风格界面：Seventh Knot 的视觉系统改造

> “像绝区零”并不等于贴满游戏图片。真正决定气质的是颜色、层级、形状、排版和动效节奏是否来自同一套规则。

<!-- more -->

## 从设计令牌开始

在修改具体组件之前，我先定义了一组全局变量：

```css
:root {
  --ik-yellow: #f6ff00;
  --ik-blue: #19a7ff;
  --ik-black: #060707;
  --ik-panel: rgba(18, 20, 21, 0.78);
  --ik-text: #f4f6f5;
  --ik-muted: #a8b0ad;
}
```

黄色负责警示和关键操作，蓝色负责连接与信息状态，近黑色承担背景和面板。之后无论是导航、文章卡片还是加载进度条，都从同一组变量取色。

## 背景不是一张图片

站点背景由原始图片、暗色遮罩、模糊效果和点阵纹理共同组成。单独看任何一层都不复杂，但叠加后会形成更接近终端界面的深度。

我使用径向渐变在不同区域补充蓝色和黄色光晕，再用规则点阵削弱大面积背景图的照片感。内容面板使用半透明背景与 `backdrop-filter`，让它们与背景建立联系，而不是像白纸一样浮在最上面。

## 形状语言比装饰更重要

Seventh Knot 没有把所有组件都做成相同圆角。主要面板使用不对称圆角、细边框和偏移阴影；小按钮则使用方形或圆形；强调区域偶尔加入斜向警示条。

这些规则共同形成“工业设备界面”的感觉：

- 细边框表示结构边界；
- 偏移阴影表示面板层级；
- 高饱和黄蓝只用于强调；
- 斜角与警示条只在局部出现。

如果每个元素都发光、旋转或带警示纹理，页面反而会失去重点。

## 文章区必须服务阅读

首页可以更具表现力，但文章正文仍然需要稳定。正文区域提高背景不透明度，限制最大宽度，增加段落行高，并降低装饰性纹理的存在感。

代码块、引用、标题和链接继续沿用 Theme Yun 的语义结构，只通过覆盖样式融入新视觉。这样既保留 Markdown 渲染能力，也减少对上游模板的侵入。

## 把覆盖样式集中管理

所有项目级样式集中在：

```text
source/css/custom_theme.css
```

主题配置通过 `_config.yun.yml` 引入该文件。集中管理的好处是，可以快速检索一个组件的桌面端、移动端和动画规则，也能明确区分上游样式与项目自定义样式。

对于必须修改的 Pug，我尽量保留原有类名，再附加 Seventh Knot 专用类。这样原主题的基础规则仍然能够工作。

## 克制使用游戏素材

游戏素材主要出现在邦布加载动画、导航图标和网页宠物中，其他视觉尽量通过 CSS 实现。这样既能保持主题气质，也不会让文章页面变成素材展示页。

同时，README 中明确说明这是非官方个人项目，相关游戏素材的权利归原权利人所有。视觉借鉴和素材使用必须与原创代码、个人内容的权属分开说明。

## 页面系统落地

同一套面板、边框、警示色和信息层级不仅用于文章页，也延伸到了分类索引与代理人档案等独立页面。

## 小结

Seventh Knot 的视觉改造不是一次主题换肤，而是建立了一套可以继续扩展的界面规则。当新增一个页面或按钮时，我不需要重新决定它应该长什么样，只需要判断它属于哪种层级、承担什么功能，再使用已有的颜色与形状语言组合即可。

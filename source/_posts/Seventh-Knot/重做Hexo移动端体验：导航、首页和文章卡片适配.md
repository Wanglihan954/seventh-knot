# 重做 Hexo 移动端体验：导航、首页和文章卡片适配

> 移动端适配不是把桌面页面缩小。真正需要调整的是信息优先级、操作方式、可视高度和触控区域。

<!-- more -->

## 先解决导航

桌面端可以长期展示导航和侧边栏，手机上却没有足够空间。Seventh Knot 使用汉堡按钮控制导航状态，并通过 JavaScript 管理以下行为：

- 点击按钮打开或关闭菜单；
- 点击遮罩关闭菜单；
- 按下 `Escape` 关闭菜单；
- 点击菜单链接后自动收起；
- 菜单打开时限制背景滚动。

按钮使用真正可聚焦的交互结构，并维护 `aria-expanded`，让键盘和辅助技术能够理解当前状态。

## 使用动态视口高度

移动浏览器地址栏会改变可视区域，单独使用 `100vh` 容易让首页底部被遮挡。因此首页同时声明：

```css
.home-sequence {
  height: 100vh;
  height: 100svh;
}
```

支持新单位的浏览器使用 `svh`，旧浏览器仍然可以回退到 `vh`。

## 处理安全区域

刘海屏、圆角屏和底部手势区域需要额外空间。首页内容、导航和下拉箭头使用 `env(safe-area-inset-*)` 参与间距计算：

```css
padding-bottom: max(72px, env(safe-area-inset-bottom));
```

这比固定增加一个很大的底部边距更准确，也不会影响普通屏幕。

## 首页内容重新排布

桌面端加载面板把邦布放在右侧；移动端则移动到面板上方。个人主页减少内边距和头像尺寸，社交图标与站点入口允许换行。

下拉箭头继续位于首页内部，并保持至少约 44px 的触控区域。云层只负责视觉，不拦截点击。

## 文章卡片不能只改宽度

手机上的文章卡片需要同步调整：

- 标题字号和行高；
- 元信息换行方式；
- 摘要最大高度；
- 卡片内边距；
- 图片和代码块的溢出行为；
- “阅读全文”入口的触控面积。

代码块允许水平滚动，图片限制为容器宽度，长链接使用换行策略，避免单个内容元素撑破整个页面。

## 避免固定元素互相遮挡

站点同时存在网页宠物、工具按钮、回到顶部和首页下拉箭头。如果它们都固定在右下角，就会互相覆盖。

解决方法不是不断增加 `z-index`，而是先分配区域：宠物靠近底部，工具按钮纵向排列，下拉箭头只在首页中间出现。移动端进一步缩小宠物尺寸，并为底部手势区域留空。

## 动效需要降级

移动设备不一定性能不足，但复杂滤镜和大面积模糊会增加合成压力。小屏幕下可以降低阴影强度、减少背景模糊，并避免同时播放太多装饰动画。

同时使用 `prefers-reduced-motion` 提供无动画模式。它不只是无障碍需求，也是一种稳定的低开销回退方案。

## 检查清单

每次调整移动端，我都会检查：

1. 导航能否通过点击、遮罩和 Escape 关闭；
2. 页面是否出现非预期横向滚动；
3. 首屏底部是否被地址栏或手势区遮挡；
4. 标题、代码块和长链接是否撑破卡片；
5. 固定按钮是否互相覆盖；
6. 禁用动画后是否仍能进入正文。

移动端最终不是桌面版本的附属品，而是 Seventh Knot 的另一种完整入口。
